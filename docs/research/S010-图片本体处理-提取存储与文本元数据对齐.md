# S010-图片本体处理-提取存储与文本元数据对齐

> 2026-09-04。触发点:安全相似系统学.pdf 深入验收时用户追问「图 1-1 呢」;图表只剩 OCR 残片,图片本体取不出;用户点名研究「类似图片本体怎么处理分析还原」,两轮追问链定界。流程按 R002;六态标准见 G002。PoC:`poc\s010-chart-geometry\`。

## 背景

reader 只取文本层(AGENTS 边界:不渲染不编辑)。文档里的图表/照片/示意图是图片本体:扫描书整页即位图,Office 家族内嵌 media 件。验收实证:安全相似系统学.pdf 图 1-1 的 OCR 残片有全部数据标签(83.4 万起到 6 万)但与年份的配对不可信;图本体无出口。

## 关键结论

1. **用户定界(第 2 轮追问链,2026-09-04)**:reader 的职责 = **自动提取文本和图片,提取的元数据对齐**(只负责提取存储图片,和文本元数据对齐)。图表模型理解不在 reader(T3 模型路线已拒绝,防复问:理解交给调用方 Agent 的多模态侧)。
2. **仓内基石全在(源码实证)**:ppocr-rs `OcrLine` 自带 `polygon: [Point; 4]` 文本区四边形坐标(几何配对可行);anydoc `Asset { media_type, origin_part, bytes }` 已抽内嵌图原字节(公开 API `to_markdown_bytes` 丢弃 assets,zip 直读绕开);hayro 渲染 PNG 管线在用(ocr.rs);image crate 读写全family。
3. **生态双通道(2026-09-04)**:模型 SOTA 是 PP-StructureV3 / PP-Chart2Table(PaddleOCR 3.0,Apache-2.0,PaddleOCR-VL 0.9B 号称文档解析超 GPT-4o;chart-to-table 在 VL 1.5 提 9.36pp);Paddle 运行时破纯 Rust 单二进制边界,ppocr-rs 无 structure 系,Rust 侧无移植;Rust 无成熟图表数字化 crate(WebPlotDigitizer 是浏览器工具,概念参照其轴标定流程)。即:模型路不可行也不需要(裁定 1),经典几何路零件齐备零新依赖。
4. **三层路线与裁定(第 1 轮)**:T1 图本体导出(figures 子命令)立项落地进主仓;T2 图表数据还原(几何配对)PoC 先行验证再裁;T3 模型路线不采纳(第 2 轮「只负责提取存储」收口)。

## 现状或实测

### T1 形态(D47 落地)

`reader figures <文件> [--pages] [--out DIR] [--format text|json]`:图本体落盘加行式清单与 json 包膜,元数据对齐字段 = 锚(页 / md 引用 / zip 部件 / 文件)、图题候选(页文本或 md 引用就近的「图N-M」行)、上下文行(图题后文本)、落盘路径、字节数、格式。

- PDF:hayro 渲染整页 PNG(扫描书页即图本体);图题与上下文从 pdf-inspector 页文本正则对齐。
- markdown:解析 `![alt](path)` 引用,相对路径存在即复制,alt 即图题。
- anydoc 家族:zip 直读图片扩展名部件(media 原字节),锚为部件路径。
- 图片文件:本体即自身,原字节复制。

### T2 PoC(poc\s010-chart-geometry\)

实测(2026-09-04,tiny 档):**机制可行、数值配列精度不足**。成立面:年份轴 12 列全还原(含 OCR 融合串 `20042005…2015` 的按位切分插值)、图例/轴名/图题/正文盒全部分离带坐标、页内第二张图正确排除;不成立面:数据标签行同样融合(变长小数粘串,固定切块不可用)与双系列标签列偏移(纯 x 最近配列偏一列)。裁定:T2 暂不进主仓,难点与迭代方向记 PoC README;figures 加调用方多模态已覆盖需求主径。
