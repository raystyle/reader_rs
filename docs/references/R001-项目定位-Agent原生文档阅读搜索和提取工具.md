# R001-项目定位-Agent原生文档阅读搜索和提取工具

> 角色：**现役定位展开**。AGENTS 一、项目定位的全文版；定位变更走 proven 方案归档。本版定位由 `docs\proven\P0002-项目重新定位-Agent原生文档阅读搜索和提取工具.md` 确立（2026-08-31），上一版措辞见该方案背景节。

## 一、一句话定位

Reader 是 Agent 原生文档阅读、搜索和提取工具：为 Agent（AI 智能体）管线设计的 Rust CLI，从本地文档读文本层——按页读、按词/正则搜、按页取。[实证: 2026-08-31 用户定位口径]

## 二、Agent 原生的设计约束

> 定位落成可执行的行为约束；新增能力逐条对照。

1. **输出稳定可解析**：行式标记输出（`页:行号:文本`、`== page N ==`），退出码 grep 语义（命中 0、无命中 1、出错 2），stdout 不出装饰性内容。[实证: 2026-08-31 tests\cli.rs 断言形态]
2. **单调用完成一件事**：无交互、无守护进程、无环境副作用；错误走 stderr。[实证: src\lib.rs run() 形态]
3. **机器可读优先于人类美观**：输出形态演进（JSON 等）以此为序，列 ROADMAP 阶段 3 首要候选。[推断: P0002 方案]

## 三、本质与边界

1. **本质**：读文档文本层，当前两个动作——`search`（找，带页码与上下文）与 `extract`（取，按页分节输出）。[实证: P0001 方案]
2. **边界**：
   - 服务对象先 Agent 后人；不做 GUI/TUI 交互式阅读器。[实证: P0002 方案]
   - 当前支持 PDF 与 EPUB（章为 EPUB 文本单元），均只读；不做渲染、编辑、OCR；扫描件与编码问题页检出后提示，不识别；docx/mobi 等其它格式按需另立项。[实证: P0003 方案]
   - 文本质量承诺只面向英文与中文内容；其它语言（日韩等 CJK 兄弟语种、RTL）不做质量承诺，文本层不可靠时以 needs_ocr 提示兜底。[实证: 2026-08-31 用户裁定]
   - 纯 Rust 单二进制；不外挂 pdfium 等二进制运行时（pdf-inspector 默认构建即纯 Rust）。[实证: cargo info pdf-inspector 2026-08-31，default features 为空]
   - Windows 起步，macOS/Linux 由 CI 三系统门禁接管验证（P0004）；依赖均跨平台，不主动破坏其它平台。[实证: 2026-08-31 .github\workflows\ci.yml]
