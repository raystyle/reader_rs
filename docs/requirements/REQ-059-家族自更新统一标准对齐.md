# REQ-059:家族自更新统一标准对齐

## Scenario

总台派单（2026-09-18 家族自更新统一标准轮，用户裁「采纳推广」）：以 browse-rs 仓 REQ-005 加 build-release 公共契约第六节为权威口径（stable 段双通道优先加 digest 锚硬校验加 semver 只升不降加自替换自证回滚；验收判据 = 同工具 self update 与管理器 update 同报已最新、各端终态同 digest），reader 已有自更新面按同口径复核出差异表，缺啥补啥；形状差异（键形）列档不统一。

## Criteria

- [x] 差异表成文（下节，件件给现状与本批动作；形状差异列档）
- [x] 双通道整对回落：镜像通道（latest.json 清单加清单所指资产）任一步传输失败整对切 GitHub；digest 锚校验在通道裁决后统一做，不符硬拒不回落
- [x] semver 只升不降：判新三态（updated / current / local_newer），本地领先报 local_newer 不动，输出行给回退指路
- [x] 自替换三步舞：旧件挪 pid 备份、新件入位、`--version` 自证五次重试（200ms 递增间隔）、证毕清备份；入位或自证失败回滚并复核终态（exe 在位），回滚受阻报自救路径（mv 指令加 issue 渠道）
- [x] 更新锁：exe 旁 `.reader-selfupdate.lock`，create_new 语义，锁内 pid 死即收割重取（linux /proc 判活，他端保守），drop 清锁盖 panic 面
- [x] 陈旧收割：持锁后清 `.reader-selfupd-*` 暂存目录与 `.<bin>.new-/.old-/.bak-` 散件（锁保证残留皆死进程所留）
- [x] 暂存落 exe 同目录（防跨文件系统 rename EXDEV；原 temp 目录暂存废弃）
- [x] ark 让位：exe 同目录 `ark-managed` 落痕或用户面 bin 符号链接入口即拦（走网络前），CTA 指 `ark update reader`；落痕生产者契约在 ark 侧（飞轮转呈）
- [x] `GITHUB_TOKEN` 别名与 `GH_TOKEN` 同取；无资产平台错误带源码安装 CTA
- [x] 兄弟二进制（rr / reader 双名）同三步舞自证，失败降级警示不阻塞自身

## 差异表

标准件对 reader 现状（对齐前）与本批动作：

| 标准件 | 对齐前现状 | 本批动作 |
| --- | --- | --- |
| 镜像优先双通道，任一步失败整对回落 | 查新步有回落（清单失败回退 GH API）；下载步钉死镜像 url，镜像下载失败直接报错不回落 | 补整对回落：镜像通道成对件（清单加下载）任一步传输失败整对切 GitHub 成对件（release API 加 download） |
| digest 锚硬校验不符拒回落 | sha256 钉死校验已有、不符报错不回落 | 达标；校验移到通道裁决后统一做，错误明示「硬拒不回落」加 issue CTA |
| semver 只升不降，本地领先报 localNewer | 只升不降已有（不降级）；本地领先与已最新同报「已是最新」 | 补判新三态与 local_newer 输出行（含回退指路） |
| 暂存落 exe 同目录防 EXDEV | 暂存落系统 temp 目录（跨文件系统 rename 风险） | 补：暂存目录 `.reader-selfupd-<pid>` 落 exe 同目录 |

| 陈旧收割 | Windows 侧 old 残留下次升级时删（部分） | 补持锁收割：暂存目录与 new/old/bak 散件全清 |

| 证败回滚并复核终态，回滚受阻报自救 | Windows rename 失败局部回滚；无自证败回滚链 | 补统一三步舞（全平台备份挪位入位）加 rollback_and_verify 复核在位，受阻报 mv 自救路径 |
| ark 管理布局让位 | 无 | 补 ark-managed 落痕与用户面 bin 链接入口拦截，CTA 走 ark |

| 无资产平台源码 CTA | 报错无 CTA | 补 cargo install --git 出口 |
| 元数据对齐（管理器同报已最新） | reader 侧 self update 幂等明示 | 验收面：self update 双态实弹；ark update 对账待总台滚 catalog 后闭环（管理器侧件） |
