# ADR-0006:历史档案清退与知识融入

## Context

REQ-048 迁移（2026-09-16）立「历史不回填、活档不搬家」口径：根四原语（PRD / GOAL / PLAN / TODO）与 INDEX 迁移期保留，proven 全文留档，mistakes 留档不再接编。运行一日后用户裁定（2026-09-17）：清退旧档，但先把存量知识完全融入 ADR 体系再删件。备选：继续留档（否，双真相漂移面大，文档检索面被旧结构污染，骨架合规面长期背着迁移期例外）；搬运归档到独立分支或目录（否，仍是仓内第二真相）。git 历史即全文备份（清退前最后完整态在 tag v0.7.0），不再需要仓内留档副本。

## Decision

删根五件（GOAL / PLAN / TODO / PRD / INDEX）与 `docs/proven/`（P0001 至 P0018）与 `docs/mistakes/`（M101 至 M105 含行级 M001 至 M018）；存量知识按下节蒸馏表融入活跃面；P / M / D 编号停用，此后仅作历史沿革标签（新坑走 ADR 或 diary，AGENTS Must 既有口径）。INDEX 代码文件位置表由 docs/README 承接；历史不改写面（CHANGELOG、diary、guides 旧三节留档、research 旧文）的旧引用断链走 md-ref-allow 在册豁免。执行清单与门禁回执见 REQ-054。

## Consequences

- 好：单一历史真相（git）替代三处仓内留档；文档检索面收敛到 dev-evo 结构（AGENTS、adr、requirements、references、guide、guides、research、diary）；AGENTS 与 docs/README 不再背迁移期例外与留档口径
- 坏：P / M / D 全文需 git 检索取阅；旧档间互链（proven 指针回指设计）失效，ADR-0001 至 0004 的 Context 已改为 git 历史口径
- 后续：本篇蒸馏表是旧档仍约束现状知识的唯一仓内落点；发现蒸馏缺口回填本表或另立 ADR

## 蒸馏表 mistakes

> 覆盖 M001 至 M018。

已承接件与承接位：M005（tests/cli.rs 正斜杠路径断言）、M006（R004 / R005 / R008 门禁裸跑不接管道口径）、M007（src/main.rs SIGPIPE 处置与 tests/cli.rs 回归）、M009（src/mirror.rs ureq 响应上限放宽）、M010（G007 PoC 验收含 stdout 纯净度）、M012（Cargo.toml flate2 纯 Rust 后端）、M015（R008 rclone 隔离目录 copy 手法）、M017（tests/mirror.rs 下载器自建父目录回归）。M011 随 tract 引擎退役失义，不承接。

原无活跃落点、随删件入册的蒸馏句（M 编号锚保留，散落代码注释与本表互指不断义）：

| 编号 | 坑与正确处理 |
|---|---|
| M001 | URL 内嵌与散文示意的 docs 前缀路径被断链扫描误报；外部仓真实引用在 md-ref-allow.txt 加锚定豁免正则，散文示意改措辞不加豁免 |
| M002 | MSYS / Git Bash 的 `/d/...` 路径喂原生 Windows 二进制报 os error 3；给原生二进制的参数一律 Windows 形态路径加双引号，MSYS 形态只留给 MSYS 工具 |
| M003 | 工具装错架构资产在 arm64 mac 报 bad CPU type；换机装工具按主机架构选资产，`file` 加 `--version` 冒烟再进门禁 |
| M004 | 退役 runner（macos-13）症状是 job 永久 queued 不报错；选 runner 标签先查 GitHub 支持列表（与 P0008 同根，R008 承接） |
| M008 | Git Bash 写 `2>nul` 落出 Windows 保留名真文件阻断 git add；bash 侧一律 `2>/dev/null`，已落出的用 `rm ./nul` 删 |
| M013 | Cargo.toml 数组表（`[[test]]` 等）插进 dev-dependencies 中间会吞后续依赖键（TOML 节序即语义）；数组表一律放文件末尾，留意 unused manifest key 警告 |
| M014 | target 里同名无扩展名旧 Linux 二进制会先于 `.exe` 被命中；pwsh `>` 重定向按行重组转 CRLF；显式写 `.exe`、bash 原样重定向保 LF、重生后 `git diff` 核对再收 |
| M016 | unix 上反斜杠字面量路径断言假失败（`with_file_name` 把整串当单文件名）；跨平台断言一律正斜杠字面量，确要测反斜杠用 `#[cfg(windows)]` 圈住 |
| M018 | 重生产物进了提交而生成源漏列，本地绿 CI 红（逐字节守卫红）；重生类提交先 `git status` 复核无未暂存源变更再推，同 sha CI 红用干净克隆加 `git diff HEAD` 对账定位 |

## 蒸馏表 四原语与 INDEX

- INDEX：代码文件位置表并入 docs/README（路径统一正斜杠）；编号表职责由 G001 与各目录 README 承接
- PRD：D 号即 REQ 号口径存 requirements/README；D01 至 D47 全文在 git（tag v0.7.0 及此前）
- GOAL / PLAN / TODO：队列与方案职责由 REQ 的 Criteria 与 trace 承接，过程细节在 diary；两件销账与指针：D42 挂账「ISSUE #1 大陆侧第三级回退演练回执后归档 P0019」由 REQ-050 五端 ark 回执实质覆盖销账（记入 ADR-0004 Consequences）；D42 镜像分发九项实现细则以 `src/mirror.rs` 注释与两个 workflow 为准（代码即真相）
