# M104-CI与发布流水线错误

> 错误速查分类文件：CI / release 流水线相关踩坑，如 runner 退役、上传竞态、资产命名冲突。行级编号 M0xx 全局递增不复用；迭代规则见 `INDEX.md` 八、错误速查。

## M004 macos-13 Intel runner 已退役，release job 永久排队

- 日期：2026-08-31
- 现象：release run 33457730048 四 job 中 `x86_64-apple-darwin`（runs-on: macos-13）排队 25 分钟以上不调度，其余三 job 早已完成。
- 根因：GitHub 已退役 macos-13 Intel runner（无可用容量），job 永远等不到执行器。
- 正确处理：Intel mac 二进制改在 macos-latest（ARM）上交叉编译：rust-toolchain action 的 `targets:` 加 `x86_64-apple-darwin`，同一 Xcode SDK 支持双架构。通用教训：CI 矩阵选 runner 标签前先确认该标签仍在 GitHub 支持列表；退役 runner 的症状是 job 永久 queued 而非报错。

## M015 rclone 对 Cloudflare R2 单件 copyto 触发 CreateBucket 403

- 首踩：2026-09-03（D42 镜像腿首跑：mirror-models.yml 与 release.yml 演练双双红在清单单件上传）
- 现象：`rclone copy <目录> R2:桶/前缀` 全部成功，随后 `rclone copyto <单件> R2:桶/路径/清单.json` 三次重试全败 `operation error S3: CreateBucket, 403 AccessDenied`；桶已存在、同凭据目录 copy 正常。
- 根因：rclone S3 后端对 copyto 的目标 fs 做 HeadBucket 探测，R2 对该探测的应答让 rclone 误判桶不存在，回退尝试建桶；桶级 token（Object Read & Write）无建桶权即 403。
- 正确处理：单件上传统一改「隔离目录 + `rclone copy`」（清单放独占目录 copy 到目标前缀，效果同 copyto）；D42 的 latest.json 与 models.manifest.json 两个发布提交点均已改。
