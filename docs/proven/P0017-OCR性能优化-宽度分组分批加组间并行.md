## 背景与问题

P0014 落地后用户裁定 19-42 秒/页（S006 实测口径）不可接受，给定目标 5-10 秒/页。

## 目标与非目标

- 目标：`--ocr` 单页 wall 时间进 5-10 秒档（多核机），文本质量不明显退化。
- 非目标：不换模型（server/v6 留 S006 待办 2）；不引 GPU；不改输出契约；不做页级并行（调用方自行并行）。

## 方案

剖析先行（引擎自带 run_with_metrics 拆三段计时），再动 vendored pure-onnx-ocr：

1. **rec 张量动态宽度**（preprocessing.rs）：上游定长 2560 padding，改为批内最长行定宽加 320 桶化（tract 按 (batch, width) 缓存可运行计划，桶化限形状数）。
2. **宽度分组分批**（engine.rs RecognitionPipeline）：按目标宽度排序后按 rec_batch_size 定长分批，批内行宽相近。
3. **组间并行**（engine.rs）：tract 0.20 无 rayon 单线程（Cargo.lock 与源码核实），一组一个 scoped worker、每 worker 独立 RecInferenceSession（会话 !Send/!Sync 不可共享，M011），worker 数封顶 `available_parallelism`，mpsc 回收结果按原序还原。
4. **rec_batch_size 按核数自适应**（src\ocr.rs）：≥16 核取 2、≥8 核取 4、否则 8。

## 实测数据

样本：安全牛 PDF 第 10 页（30 行正文），release，本机 32 核。

| 配置 | wall | 说明 |
| --- | --- | --- |
| P0014 基线（定长 2560） | 20.5s | rec infer 19.6s 占 96%，det 仅 0.73s |
| 动态宽度 1920 | 25.9s | 更慢——batch 维度未拆，总列数没降 |
| 动态宽度加桶 640 | 12.9s | SVTR 注意力对宽度近似平方级，宽度才是主轴 |
| 宽度分组分批（batch 8，4 组并行） | 4.9s | 组间并行 4 worker |
| 同上 batch 4 / batch 2 | 3.6s / 3.0s | 8 / 15 worker |
| 真样本两页端到端（reader --ocr） | 11.1s | 约 5.5 秒/页，达标 |

[实证: 2026-09-03 本机 release 多轮]

质量对照（同页 S006 摘录口径）：正文行置信 0.99 持平；若干 P0014 掉字反而修复（「法律保护」「书面许可」「予以追究」此前缺字）；水印碎片行由空串变为少量噪声短行（「X」「ca」），属 needs_ocr 不可靠文本域内变化。[实证: 2026-09-03 diff 对照]

## 备选方案

| 方案 | 取舍 |
| --- | --- |
| 宽度分组分批加组间并行（选定） | 实测 20.5s 到 3-5.5s；不动模型不换引擎 |
| 渲染 scale 降采样 | 无效杠杆：rec 目标宽由行纵横比定，与渲染 scale 无关；只降 det 质量 |
| det_limit 下调 | det 只占 0.73s，无收益 |
| 页级并行 | 整书 wall 降但单页延迟不降，偏离用户目标；留调用方 |

## 实施过程与经验

- 先量后改：run_with_metrics 当场定位 rec 占 96%，避免去优化 det。
- 直觉会错：动态宽度不加分组反而更慢（batch 内行长方差大时总列数未必降）；注意力平方级意味着「减宽」比「减行」值钱。
- tract 0.20 单线程无 rayon；并行只能在会话外做，会话 !Send/!Sync 故每 worker 独立加载（25ms/个，模型 16MB，量级可承受）。
- vendor 改动跑 PoC 要重建对应 bin（cargo build --bin 只建指定目标，吃过一次旧二进制误读）。

## 验收标准

- 单页 wall 进 5-10 秒档：第 10 页 3.0s（32 核 batch 2），真样本两页 11.1s（约 5.5 秒/页）。[实证: 2026-09-03]
- 质量不明显退化：正文置信持平、部分掉字修复；水印噪声入档记录。[实证: 2026-09-03 diff]
- 门禁三件加 rumdl 三件套全绿，既有用例零改动。[实证: 2026-09-03]
