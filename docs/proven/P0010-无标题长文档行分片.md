## 背景与问题

P0009 后 anydoc 家族按顶层标题分节，但无标题文档（真实中文工程文档常见手动加粗伪标题，anydoc 忠实不伪造成标题）整篇一节：`--pages` 不可细分、`--offset/--limit` 按单元分页失效。用户点名收窄该限制。

## 目标与非目标

- 目标：
  - 全文无顶层标题的文档按**固定行预算**分片为 `part` 单元（`UnitKind::Part`，节头 `== part N ==`），单元号 1 起。
  - `--pages` / `--offset` / `--limit` / 搜索上下文对 part 单元照常工作。
  - 有标题文档行为零变化（仍是 `section`）。
- 非目标：
  - 不做行预算 CLI 旗标（常量先行，真实需求出现再提）。
  - 不处理「有标题但单节超长」的再分片（限制收窄为该窄场景，CHANGELOG 注明）。
  - 不做语义分节（段落聚类、伪标题识别：加粗段不当标题是 anydoc 的忠实行为，不推翻）。

## 方案

`src\anydoc.rs`：`markdown_to_units` 拆两步：先按现状分节并带出「是否出现过顶层标题」信号；无标题时把唯一节按 `PART_LINE_BUDGET`（200 行）分片。分片在空行丢弃之后计数（行号口径与现有节一致）。

```text
markdown → 顶层标题分节（现状）
  ├─ 有标题: Vec<section>，UnitKind::Section（不变）
  └─ 无标题: 单节按 200 行切 Vec<part>，UnitKind::Part
```

预算取 200：PDF 页约 40 到 60 行、50 页文档约 1500 行得 8 片，分页粒度与既有单元量级相称；小于 200 行的无标题文档仍整篇一节（`== part 1 ==`）。

## 备选方案

| 方案 | 取舍 |
| --- | --- |
| 固定行分片（选定） | 透明可预测（agent 可算出 `--pages 1-3` 覆盖前 600 行）；实现十行 |
| 段落块聚类 / 伪标题识别 | 引启发式与不稳定性；加粗段不伪造成标题是 anydoc 忠实行为 |
| `to_document` 块边界对齐 | 模型块与 markdown 行对齐脆弱，收益不配复杂度 |
| 不分（现状） | 用户点名收窄，弃 |

## 实施步骤

1. 立项与本方案登记，三原语同步。
2. `src\anydoc.rs`：`UnitKind::Part`（document.rs）、分节信号、`chunk_lines`；单元测试更新与新添。
3. `tests\cli.rs`：CSV 长表夹具（300 行）走 part 分片断言；既有用例零改动回归。
4. 文案：introspect（llms/skill 节头口径加 part）、SKILL.md 再生成、README、CHANGELOG Unreleased。
5. 门禁三件加 rumdl 三件套；真样本回归（渗透方案 docx 180 行仍单 part）。

## 风险与回滚

- 风险：无标题判定与分片把表格从中间切开（一半在 part N、一半在 N+1）。缓解：接受（与 PDF 页切表格同语义）；回滚 `git revert` 单模块即回。
- 风险：part 与 section 混淆调用方。缓解：节头标签明确区分；CHANGELOG 记行为变化。

## 实施过程与经验

- 实际怎么做：按步骤走完。`markdown_to_units` 重构为 `split_markdown` 返回（节列表，有无顶层标题）二元组，无标题走 `chunk_lines(200)`；`UnitKind::Part` 进 document.rs。单测 5 改 3 增（分片尺寸 200/200/50、短文单 part、空文档零单元）。
- 与计划偏差：方案称「既有用例零改动」，实际 CSV 小文档用例的 `== section 1 ==` 断言随行为改 `== part 1 ==`，这正是本方案的行为变化（无标题文档标签由 section 改 part），属预期内修正，已在 CHANGELOG 记为行为变化。
- 沉淀的经验：单元种类是输出契约的一部分，改分节规则先扫一遍既有断言里的节头字符串；`kind` 字段进 JSON 的用例（断言 `"kind" == "part"`）比纯文本节头断言更抗装饰变化。
