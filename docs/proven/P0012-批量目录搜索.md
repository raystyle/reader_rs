## 背景与问题

Agent 面对「一个目录里哪份文档提到 X」时只能逐文件调 search。挂账候选「目录批量扫描」点名立项；首刀做**批量搜索**（inventory 类清单输出非首刀）。

## 目标与非目标

- 目标：
  - `reader search <目录> <关键词>` 递归扫支持格式（.pdf 加 anydoc 家族），逐文件搜索。
  - text 形态命中行升级为 `路径:单元:行号:文本`（上下文行 `路径:单元-行号-文本`）；json 形态 `hits[]` 增 `file` 字段（`--filter 'hits[].file'` 可裁剪）。
  - 单文件模式输出与退出码契约**零变化**。
  - 错误隔离：坏文件 stderr 一行 `reader: 跳过 <路径>: <原因>` 后继续；目录无支持格式文件退出 2。
  - 遍历序确定（路径排序），输出稳定可解析。
- 非目标：
  - 不做批量 extract（agent 逐文件取即可）；不做 inventory/清单子命令；不做并发（先正确后快）；`--pages` 目录下不可用（退出 2 报错）。

## 方案

新模块 `src\batch.rs`：递归走目录（std::fs，路径排序，仅支持扩展名），逐文件 `document::extract` 加 `search::search`，聚合输出（text/json 两形态）。`document.rs` 抽 `is_supported(&Path)` 公共谓词（分派与批量共用同一格式真源）。`lib.rs` run_search 入口按 `is_dir()` 分流。

退出码：任一文件命中 0 / 全无命中 1 / 目录不可读或零支持文件 2。needs_ocr 警示逐文件 stderr（stdout 保持纯命中）。

## 备选方案

| 方案 | 取舍 |
| --- | --- |
| 扩展 search 收目录（选定） | CLI 面不加命令；单文件契约不动 |
| 新 `scan` 子命令 | 首刀语义就是搜；inventory 留后续按需 |
| walkdir crate | std 递归约 20 行，不为排序走表拉依赖 |

## 风险与回滚

- 风险：Windows 路径含 `C:` 冒号干扰 `路径:单元:行号` 解析。缓解：文档写明「从右取三段冒号」；json 形态天然免疫。回滚：batch 分流独立模块，revert 即回。
