# 2026-09-18 家族自更新标准对齐与封版 0.9.0

> 来源：总台派单（家族自更新统一标准轮，用户裁「采纳推广」）：按 browse REQ-005 加 build-release 公共契约第六节同口径复核 reader 自更新面，缺啥补啥，形状差异列档。

## 概貌

标准先读（browse-rs REQ-005 与其 self_update.rs 实现面、common-contract 第六节），对照 reader 自更新面出差异表（REQ-059 在册）。达标件：digest 锚硬校验、只升不降、pid 后缀防互踩、暂存加 rename 原子替换。实缺口七件全补：镜像通道下载失败不回落（补整对回落，digest 校验移通道裁决后统一硬拒）、本地领先与已最新同报（补判新三态 local_newer 输出行）、无更新锁（补 create_new 加死 pid 收割，linux /proc 判活他端保守）、无陈旧收割（补持锁清暂存目录与 new/old/bak 散件）、暂存落系统 temp 跨文件系统（补落 exe 同目录）、无自证回滚（补三步舞：pid 备份、入位、--version 五次重试自证、证败 rollback_and_verify 复核在位、受阻报 mv 自救加 issue 渠道）、无 ark 让位（补 ark-managed 落痕与用户面 bin 链接入口拦截，消费面先行，生产者契约 ark 侧在途）。顺补 GITHUB_TOKEN 别名与无资产平台源码 CTA。形状差异列档不统一：reader 镜像面是 latest.json 聚合清单（Tauri 形状，内嵌 sha256 锚）对 browse 的 stable 滚动段（.sha256 边车锚），判据同构。封版 0.9.0（能力新增取 minor，R008 判据）。

## 关键裁决

- digest 不符不放进通道回落面：传输失败（清单坏、404、网络）整对回落，哈希不符是安全事件硬拒，两类错误分道（browse 同形）
- 暂存从 temp 目录改 exe 同目录：EXDEV 面，browse 实证过的坑
- 兄弟二进制（rr 双名）同三步舞同自证，失败降级警示维持既有容忍面（browse 单二进制无此面）
- ark 让位消费面先行：无落痕即常态自更新，不改自管安装行为，待 ark 侧生产落痕后自然生效
- 回执「在 tag 内」断言附 merge-base 自证（上轮纠错单教训，memory 在册）

## 得失

- 得：自更新面达家族统一口径，差异表成档；单测九件含 ark 拦截走网络前实证与收割面边界；herdr 评审闸门首跑（reader-codex-review 格带起，仓内 cwd 信任屏替答一次过）
- 失：ark update 对账验收待总台滚 catalog 后闭环（管理器侧件，非本仓可闭环）
- 过程坑三枚：edition 2021 无 let 链（browse 是 2024，照抄两处改嵌套 if）；Outcome 与 LockGuard 补 Debug 派生（unwrap_err 断言面）；WSL 盘两度打满（browse 同波工位并行建 26G，总台热扩 100G 根除）
- 评审记坑（F1，重要）：中断窗口加收割等于唯一副本删除面。三步舞备份挪出与新件入位之间崩进程，`.<bin>.bak-<pid>` 是唯一可恢复副本；持锁收割若无条件清 bak，下次一跑就把救援副本删光。修法：二进制在位才视为陈旧垃圾，缺位保留并 stderr 指路 mv 复原。同源教训：chmod 夹在两 rename 间失败会把安装位打空（G1，前置解决）
