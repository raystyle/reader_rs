## 关键裁决

- 发送体即签名体：ureq send_json 序列化 pretty 形，与 serde_json::to_string 不同字节；签名基覆 compact 形而线上发 pretty 形必被服务端验签拒。改按字符串原样发送（AsSendBody for String）。此坑由回归测试「测试公钥回核签名」当场逮住（第一次实跑即红），测试先行实证有效
- 公钥不走 env：REQ-063 裁「公钥作为常量集成到各仓 CLI 内」身份分发面，kid 运行推导与常量对账防漂移
- issue list 恒带 more=1：服务端「before 在场或 more=1 才出 has_more」，客户端恒索取精确翻页判定，饱和启发式仅作缺字段兜底
- close 两连发在客户端（result 加 status done）：服务端只校验前提不代发，客户端保持单命令关单体验
- kind/digest/title 客户端先校验与服务端同则（digest 64 位小写 hex；服务端正则 [0-9a-f] 同则）

## 得失

- 得：issue 面升级为账本真源（append-only 可回溯），产物沉淀面（artifact）首进 CLI；签名道全链回归可回核
- 失：issue new 必填 acceptance 比 --body 旧形多一字段（契约升级成本）；密钥丢失即写面失能（总台重登记可换新对）
- 坑两枚：测试把 seed 字节当公钥回核（公钥须从 SigningKey 派生）；lib 单测两件 env 测试并行互踩 remove_var（合一串行）
