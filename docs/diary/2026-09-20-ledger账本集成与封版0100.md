# 2026-09-20 ledger 账本集成与封版 0.10.0

> 来源：总台令集成 ledger 标准 issue 与 artifact 命令族（契约 = ohmycloud REQ-063，服务已上线 ledger.ohmygh.com），替代旧 issues.ohmygh.com 面，完毕封小版本。

## 概貌

契约先读（REQ-063 全文加工人侧 workers/ledger/src/index.ts 源码：路由、body 字段、家族翻页回执形状、verifyEd25519 签名基逐字），客户端面按服务端真形定形，零猜测。新增 src/ledger.rs：签名道（Ed25519 五头，签名基七行同构）、私钥加载（READER_LEDGER_KEY 环境或 ~/.config/reader/ledger-key 密档，不进仓不进 argv）、幂等键随机生成加 409 换键重试一次、issue 四命令加 artifact 四命令的 typed 面。CLI：issue new/list/show/close 加 artifact publish/attest/promote/list，行式与 json 包膜沿仓内惯例，家族翻页标准保持（limit 100 加 before 加 has_more 加 count 语义）。旧 src/issue.rs 与 READER_ISSUES_API 面删除（旧服务保役过渡期属总台切换策，本仓客户端不再指向）。密钥：openssl 生成 Ed25519 keypair，公钥 JWK 与 kid 内置常量（单测对账 kid_of_jwk == KEY_ID），私钥 seed 落本地密档 0600。封版 0.10.0（能力新增取 minor）。

## 关键裁决

- 发送体即签名体：ureq send_json 序列化 pretty 形，与 serde_json::to_string 不同字节；签名基覆 compact 形而线上发 pretty 形必被服务端验签拒。改按字符串原样发送（AsSendBody for String）。此坑由回归测试「测试公钥回核签名」当场逮住（第一次实跑即红），测试先行实证有效
- 公钥不走 env：REQ-063 裁「公钥作为常量集成到各仓 CLI 内」身份分发面，kid 运行推导与常量对账防漂移
- issue list 恒带 more=1：服务端「before 在场或 more=1 才出 has_more」，客户端恒索取精确翻页判定，饱和启发式仅作缺字段兜底
- close 两连发在客户端（result 加 status done）：服务端只校验前提不代发，客户端保持单命令关单体验
- kind/digest/title 客户端先校验与服务端同则（digest 64 位小写 hex；服务端正则 [0-9a-f] 同则）

## 得失

- 得：issue 面升级为账本真源（append-only 可回溯），产物沉淀面（artifact）首进 CLI；签名道全链回归可回核
- 失：issue new 必填 acceptance 比 --body 旧形多一字段（契约升级成本）；密钥丢失即写面失能（总台重登记可换新对）
- 坑两枚：测试把 seed 字节当公钥回核（公钥须从 SigningKey 派生）；lib 单测两件 env 测试并行互踩 remove_var（合一串行）

## 增记 CI 私有 git 依赖凭据

收口批首推 CI 三系统红：ledger-rs 是私仓，runner 匿名 git 拉取即拒（本地有 ssh key 无感）。修法：ci.yml 与 release.yml 各加「私有 git 依赖凭据」步（git config insteadOf 重写 github.com 到 x-access-token 形，token 走仓库 secret PRIVATE_GIT_TOKEN，空则跳过该步）；secret 站侧自灌（gh auth token 直传 API，不经对话，同 READER_LEDGER_KEY 裁）。推后 run 35521613454 三系统绿。追记：家族各仓（hst 等已引 ledger-client）CI 同坑待爆，凭据步形状可复用；建议总台周知或 ledger-rs 转公。
