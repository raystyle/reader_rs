## 自省

- **研究提问要问全局**：S004 只对「docx 怎么读」局部优化，没问「要不要借机统一引擎」，初判被推翻是提问粒度错了，不是证据错了。引擎级选型先问架构意图。
- **保真 fixture 是引擎评估的硬门槛**：三个候选里两个死在同一道实体题上；「营销口径 100% pass rate」不可采信，自造 fixture 一跑见真章。
- **集成测试首跑就抓到 EPUB 章界丢失**（rbook 章标题在 head/title，anydoc 只认正文标题）：夹具与真实结构的差异点正是行为变化的信号。
- 真实中文工程文档的加粗伪标题（`**1.1 xxx**`）让 anydoc 忠实但「无节可分」——已知限制记入 README/CHANGELOG，不臆造标题。
- **M005（同日发布暴露）**：`Path::join` 反斜杠拼仓内路径，Windows 全绿、CI linux/macOS 红——本地三件门禁替代不了跨平台 CI，封版前推 main 让 CI 先跑一遍本可免掉重切 tag。发布侧：取消带病 run、删半成品 release、tag 重指修复 commit，四 job 全绿 8 资产齐，本机 sha256 与三格式实测过。

## 第二轮：P0010 分节与 S005 TOON 销案

> 同日晚，用户点名两项后的第二轮。

- 用户点名两项：无标题长文档分节、TOON。
- **P0010 达成**：无标题文档按 200 行分片为 `part` 单元（`UnitKind::Part`），`--pages` 与分页恢复可用；有标题文档零变化。300 行 CSV 夹具验证 2 片与 `--pages 2` 选择；真样本渗透方案 180 行单 part、测试V2 仍 15 section。与方案偏差一处：CSV 小文档用例的 section 断言随行为改 part（预期内行为变化，CHANGELOG 已记）。
- **S005 结论不引入 TOON**：Reader 真实输出三样本双编码器实测——中文 search 更费 21% 到 26% token、英文带上下文更费 3.1%、大 extract 仅省 0.9% 到 1.5%；且 toon-format 0.5.0 对 `before[]/after[]` 嵌套小数组的编码输出自家解码器解不回。根因是形状不匹配：TOON 省的是同构表格的键重复，我们的包膜是异构嵌套，中文正文 token 由 CJK 主导。S002 遗留假设销案，TOON 出候选清单。
- 自省：S002 当年把 incurs 的默认照搬为候选，没先问「我们的输出形状在不在它的收益区」——同 S004 的教训一脉：**搬别家实践先对形状，再谈默认**。

## 第四轮：Linux 实机验收 R004，发现并修 M007

> 同日第四轮，WSL2 接管机按 R004 清单复跑 P0011-P0013。

- 门禁与文档门禁全绿：fmt 0 diff、clippy 0 告警、test 15 单元 + 43 集成（与 Windows 基线同数）；rumdl 41 文件零告警、断链 0、标题括号 0。
- 真样本五路过：O'Reilly PDF 399 页头、有标题 docx 45 节、无标题参数表 docx part 1、legacy.doc 保真、材料目录递归命中 pptx + json 裁剪、负例 1/2。
- **M007**：批量搜索接 `| head` 在 Linux panic（exit 101 + stderr 栈），Windows 不可复现——Rust 默认忽略 SIGPIPE 所致。修法即 ripgrep 惯例：`main()` 恢复 `SIGPIPE` 默认处置（unix-only，libc 升直接依赖），回归测试用超管道缓冲（64KB）的大输出夹具钉死「死因是信号 13 而非写完」。修后 141 静默零 stderr，debug 与 musl 静态件双验。
- musl 本地预建过：zstd-sys 在 musl-gcc 编译无恙（P0013 首验点转实证），statically linked，版本可跑。
- 自省：R004 清单自己写着 `| head`，预期值照 Windows 抄了「exit 0」——清单跨平台时，**预期值也要跨平台审**；好在验收机就是发现机。
