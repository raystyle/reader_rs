# 2026-09-02-S006内嵌OCR选型研究与PoC实证

> 当天总结与自省。

## 做了什么

- 触发：用户用 reader 抽安全牛扫描 PDF（81 页全 needs_ocr），点名研究全平台小型内嵌 OCR。
- 双通道普查九候选：ocrs（拉丁限定出局）、oar-ocr / paddle-ocr-rs / rapidocr-core（全绑 ort 原生运行时）、rusto-rs（MNN）、franken_ocr（3B 非小型）、leptess（C FFI）均出局或边界外；选中 pure-onnx-ocr（tract 纯 Rust）加 hayro（纯 Rust 渲染）实证。
- PoC（`target\poc-ocr`）：ModelScope RapidOCR 仓下载 PP-OCRv5 mobile 三件（20.5MB，SHA-256 校验）；hayro 渲染 588ms/页；OCR 19 到 42 秒/页；中文正文置信 0.9 以上，mobile 模型有系统性掉字。
- S006 落盘，INDEX/GOAL/TODO 同步。

## 自省

- 样本定性一开始想当然了：81 页 needs_ocr 里只有第 1 页是真扫描图，其余是乱码文本层（无图可抽，必须渲染）。先探结构再定管线，省得给「抽图路径」做无用功。
- pure-onnx-ocr 0.1.0 有两个实测坑（tract value_info 冲突、rec max_width 320 硬编码），都当场解掉并沉淀进 S006；若立项落地，vendor 或 fork 是绕不开的姿势，上游 0.1.0 停更 9 个月要有自己维护的预期。
- 性能 19 到 42 秒/页是 agent 场景可接受、交互场景不可接受的量级，落地时按异步兜底设计，别进热路径。
