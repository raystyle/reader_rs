## 概貌

自查命中同型三件：CLI 默认 limit=50（lib.rs clap 定义，低于服务端上限 100，open 集超 50 后旧条目默认面隐形，静默截断与 browse 同型）；返回条数打满 limit 零提示；count 语义（本次返回条数非在册总数）未写明。修法照 browse 配方等价落地：默认提至 100（help 面自动带 `[default: 100]`）；`run_issue_list` 返回条数等于 clamp 后上限时 stderr 一行截断提示（指路 `--status`/`--tool` 收窄或网页面），stdout 保纯数据、两形态同示；List 命令描述与 `--limit` 帮助写明默认值、上限与 count 语义，README 与 `--llms` curated 行同步（三处同步纪律），手册快照重出。测试加 `list_saturation_hint_cli_face`：复用本 target 一次性 HTTP 服务基建走 CLI 面断言（打满出提示、不满不出），`--limit 1` 对恰好 1 条在册同提示属语义正确（无法区分还有没有更多）。

## 实弹

`reader issue list --limit 1` 对真 API：stdout 首行恰为上游 #52 本单（新到旧第一名），stderr 出提示行原文「reader: 返回条数已达上限 1（可能截断）；--status 或 --tool 过滤收窄，或网页面 issues.ohmygh.com 看全量」，exit 0 [实证: 2026-09-19 本机 release 件输出]。坑一枚：tests/issue.rs 引 predicates 断言 `.not()` 需 `predicates::prelude::*` 入域（ContainsPredicate 无布尔扩展方法）。
