# G006-测试体系细则-六层分层与各层标准

> 角色：**本仓测试体系总规范**：把测试分为六层，各定「测什么、落在哪、什么叫过、何时跑」。断言与命名细节、依赖白名单、门禁流程仍见 `G005-测试标准细则-分层断言与门禁流程.md`；本细则不管怎么写断言，只管分层口径。
> 依据：D28（2026-09-03 用户点名六层定标）；G005 分层地基；R004 / R005 实机验收清单；tests\ab\ A/B 层（D29）。事实性断言标六态，标准见 G002。

## 一、六层总览

| 层 | 回答的问题 | 落点 | 运行时机 |
| --- | --- | --- | --- |
| 单元 | 单函数对不对 | 源码同文件 `#[cfg(test)] mod tests` | 本地门禁（每次） |
| 集成 | 公开契约对不对 | `tests\*.rs`（assert_cmd 跑二进制） | 本地门禁（每次） |
| 冒烟 | 核心路径活着没 | `tests\cli.rs` 冒烟组加真样本最小命令 | 门禁加发版资产验收 |
| 回归 | 改动破没破旧行为 | 集成测试全网加真样本行为基线（本细则三节） | 动提取/搜索/OCR 管线后 |
| 验收 | 满足需求口径没 | PRD 达成标准加 R004/R005 实机清单 | 里程碑与发版前 |
| A/B | 两变体谁更好 | `tests\ab\` 加 `.tools\ab_run.py` | 选型裁决时手动跑 |

原则：下层全绿才谈上层；上层发现的问题尽量下沉为下层的用例（bug 修复先写失败测试，G005 红绿循环）。

## 二、各层标准

### 1. 单元测试

- **测什么**：私有 API、单函数边界、错误路径、不变量（如页范围解析、`parse_model_size`）。
- **落点**：源码同文件 `#[cfg(test)] mod tests`，`use super::*`。
- **什么叫过**：`cargo test --locked` 全绿；正式构建不含测试代码。
- **规则**：能用集成覆盖就不用单元（G005 一节）。[实证: rust-guidelines M-INTEGRATION-TESTS]

### 2. 集成测试

- **测什么**：公开 API 与对外契约：退出码 0/1/2、stdout 标记行、stderr 警示、JSON 包膜字段。
- **落点**：`tests\*.rs`，每文件独立 crate；夹具现造（lopdf 造 PDF、rbook 造 EPUB、zip 造 docx），期望值来自写入的已知文本。
- **什么叫过**：本地门禁三件（fmt / clippy / test --locked）全绿。
- **规则**：正负例成对、负例 `dies_` 前缀、只断稳定字段（G005 二节）。

### 3. 冒烟测试

- **测什么**：最小活体：`reader --help` / `--version` 退出 0；核心命令在最小输入上可跑。
- **落点**：`tests\cli.rs` 冒烟组；真样本冒烟为一条 extract 加一条 search（断退出码）。
- **什么叫过**：退出码符合 grep 语义，秒级完成。
- **规则**：冒烟只断「活着」，质量判断归验收与 A/B；发版资产解包后必跑一次（版本号加一条 search）。[实证: v0.2.1 与 v0.3.0 发版验收均含资产冒烟]

### 4. 回归测试

- **测什么**：改动不破旧行为。集成测试全体即回归网；真样本行为基线兜底「测试没写到的真实行为」。
- **基线登记**（改行为必须有意为之并同步改基线记录）：

| 样本 | 形态 | 已知行为基线 |
| --- | --- | --- |
| 安全牛水印 PDF（external，不入仓，sha256 见 `tests\ab\manifest.json`） | 81 页扫描混合 | search 命中 25 处且序列与 S001 基线一致 [实证: P0006 起多轮回归]；第 10 页 OCR 检查点见 `tests\ab\expectations\anniu-p10.json` [实证: S008] |
| `tests\ab\assets\scan-cjk.pdf`（入仓合成） | 单页无文本层 | extract 报 `[needs_ocr: scanned]` [实证: 2026-09-03 本机]；OCR 检查点见 expectations（渲染源文本） |

- **什么叫过**：基线行为逐项一致；差异必须能回指某次有意变更（P 编号）。
- **何时跑**：动提取、搜索、OCR、输出契约的代码后必跑真样本回归。

### 5. 验收测试

- **测什么**：对照需求口径验收：PRD 条目的达成标准、用户给定的可观察判据（如「5 至 10 秒一页」「掉字点全修」）。
- **落点**：`R004` / `R005` 实机验收清单（门禁、真样本、交叉预建）；发版验收（资产 sha256 官方校验、解包冒烟、self update 路径）。
- **什么叫过**：判据逐条实测满足并记录证据（机器、日期、数字）；oracle 独立于实现。
- **何时跑**：里程碑、发版前、平台接管时。

### 6. A/B 测试

- **测什么**：同一批对象资源上两个变体的**质量**（检查点命中、行召回、判别点）与**性能**（wall、秒/页）对比，支撑选型裁决。
- **落点**：`tests\ab\`（manifest 对象资源登记、expectations 检查点、reports 报告存档）；跑批器 `.tools\ab_run.py`；协议见 `tests\ab\README.md`。
- **什么叫过**：A/B 是对比不是门禁，跑批器退出码只表跑批成败；差异由人裁决，结论回填 S 文档（六态）。
- **规则**：检查点必须有独立来源（合成样本用渲染源文本，真样本用研究实证清单），禁止从被测输出反抄期望（G005 重言式禁令适用）；报告带日期与机器信息，不覆盖旧报告。

## 三、与其它细则的分工

| 细则 | 管什么 |
| --- | --- |
| G005 | 怎么写断言与命名、测试依赖白名单、门禁三件、AI 自检 |
| R004 / R005 | 实机验收的操作清单（验收层的执行手册） |
| 本细则 G006 | 六层各是什么、落在哪、什么叫过、何时跑 |

## 四、验收自查

加测试或建测试面时自查：

1. 落点对层：单元在 cfg(test)、集成在 tests\、A/B 在 tests\ab\
2. 每层「什么叫过」能说清；质量判断没塞进冒烟
3. 期望值与检查点有独立来源
4. 真样本基线变化能回指有意变更
5. A/B 报告落 reports\ 且裁决回填 S 文档
