# G006-测试体系细则-六层分层与各层标准

> 角色：**本仓测试体系总规范**：把测试分为六层，各定「测什么、落在哪、什么叫过、何时跑」。断言与命名细节、依赖白名单、门禁流程仍见 `G005-测试标准细则-分层断言与门禁流程.md`；本细则不管怎么写断言，只管分层口径。
> 依据：D28（2026-09-03 用户点名六层定标）；D31（测试程序用 uv 运行时 Python 脚本）；G005 分层地基；R004 / R005 实机验收清单；tests\ab\ A/B 层（D29）；2026-09-03 用户供稿《Rust 规范测试流程》要点（原生三层对目的流程层的框架修正）。事实性断言标六态，标准见 G002。

## 一、框架：原生地基三层对目的流程四层

Rust 工具链原生内置的测试只有三层：**单元测试、集成测试、文档测试**。`cargo test` 按固定顺序跑三段（源码内 cfg(test) 单元、`tests\` 集成、`///` 文档测试），前一段失败则后段不执行，天然形成「快测试挡住慢测试」的分层门禁。[经验: 2026-09-03 用户供稿引 Rust 官方组织约定，本仓未逐条复核]

**冒烟、回归、验收、A/B 不是官方框架概念，是按目的划分的流程层**：没有现成的「冒烟框架」或「A/B 框架」，靠测试组织约定加脚本载体加 CI 流程拼装出来。本仓的拼装方式：冒烟/回归/验收归 cargo test 体系（独立 test target 单独调度，D31 第 2 轮裁定），A/B 归 uv 运行时 Python 跑批脚本。[实证: 2026-09-03 tests\smoke.rs / regress.rs / accept.rs 与 .tools\ab_run.py 落地]

文档测试（原生第三层）是可执行文档兼最贴近用户用法的回归防线；本仓公开面以 CLI 为主、lib 公开面小，文档测试暂少，列入演进候选（G005 五节）。[经验: 用户供稿引《Effective Rust》第 30 条亦建议 CI 跑 cargo test --examples]

## 二、六层总览

| 层 | 类别 | 回答的问题 | 落点 | 运行时机 |
| --- | --- | --- | --- | --- |
| 单元 | 原生地基 | 单函数对不对 | 源码同文件 `#[cfg(test)] mod tests` | 本地门禁（每次） |
| 集成 | 原生地基 | 公开契约对不对 | `tests\*.rs`（assert_cmd 跑二进制） | 本地门禁（每次） |
| 冒烟 | 目的流程 | 核心路径活着没 | `tests\smoke.rs`（cargo test --test smoke） | 门禁加发版资产验收 |
| 回归 | 目的流程 | 改动破没破旧行为 | `tests\regress.rs` 真样本基线加集成测试全网 | 动提取/搜索/OCR 管线后 |
| 验收 | 目的流程 | 满足需求口径没 | `tests\accept.rs` 可机检项加 PRD 达成标准加 R004/R005 实机清单 | 里程碑与发版前 |
| A/B | 目的流程 | 两变体谁更好 | `tests\ab\` 加 `.tools\ab_run.py` | 选型裁决时手动跑 |

原则：下层全绿才谈上层；上层发现的问题尽量下沉为下层的用例（bug 修复先写失败测试，G005 红绿循环）。回归集的唯一正规生长方式：每次修 bug 附带一个能复现原 bug 的用例。[经验: 用户供稿引 Rust 社区风格指南]

**载体规则（D31，第 2 轮用户裁定）**：单元、集成、冒烟、回归、验收五层都归 **cargo test 体系**（冒烟/回归/验收为独立 test target：`cargo test --test smoke` / `--test regress` / `--test accept` 单独调度）；只有 **A/B 跑批用 uv 运行时 Python**（`.tools\ab_run.py`，PEP 723 单文件头，stdlib 优先）：A/B 是对比跑批不是断言门禁，脚本载体更灵活。

## 三、各层标准

### 1. 单元测试

- **测什么**：私有 API、单函数边界、错误路径、不变量（如页范围解析、`parse_model_size`）。
- **落点**：源码同文件 `#[cfg(test)] mod tests`，`use super::*`。
- **什么叫过**：`cargo test --locked` 全绿；正式构建不含测试代码。
- **规则**：能用集成覆盖就不用单元（G005 一节）。[实证: rust-guidelines M-INTEGRATION-TESTS]

### 2. 集成测试

- **测什么**：公开 API 与对外契约：退出码 0/1/2、stdout 标记行、stderr 警示、JSON 包膜字段。
- **落点**：`tests\*.rs`，每文件独立 crate；夹具现造（lopdf 造 PDF、rbook 造 EPUB、zip 造 docx），期望值来自写入的已知文本。
- **什么叫过**：本地门禁三件（fmt / clippy / test --locked）全绿。
- **规则**：正负例成对、负例 `dies_` 前缀、只断稳定字段（G005 二节）。

### 3. 冒烟测试

- **测什么**：最小活体：`reader --help` / `--version` 退出 0；核心命令在最小输入上可跑。
- **落点**：`tests\smoke.rs`（3 项：version/help 活体、search 双向退出码、扫描件 needs_ocr）。
- **什么叫过**：`cargo test --test smoke` 全绿，秒级完成。
- **规则**：冒烟只断「活着」，质量判断归验收与 A/B；发版资产解包后必跑一次（版本号加一条 search）。[实证: v0.2.1 与 v0.3.0 发版验收均含资产冒烟]

### 4. 回归测试

- **测什么**：改动不破旧行为。集成测试全体即回归网；`tests\regress.rs` 跑真样本行为基线、`tests\snapshot.rs`（insta）守公开输出全量格式，兜底「断言没写到的漂移」。
- **快照纪律**：快照变更必须人工审 diff，禁止盲目 accept；首跑新快照以失败形式产出 `.snap.new`，审内容后改名入库。[实证: 2026-09-03 D34 首跑流程]
- **基线登记**（改行为必须有意为之并同步改基线记录；external 样本缺失或 sha256 不符时对应用例跳过并告警）：

| 样本 | 形态 | 已知行为基线 |
| --- | --- | --- |
| CLR 书《Command-Line Rust》（O'Reilly 2022，external 不入仓，sha256 `05fc14c5…`，路径见 `tests\regress.rs`） | 399 页文字版 | search `assert_cmd` 命中 25 行且页号序列与 S001 一致 [实证: 2026-09-03 本机 release]；extract 页标记 399 [实证: 2026-09-03；S001 记 390 系旧管线口径] |
| 安全牛水印 PDF（external 不入仓，sha256 见 `tests\ab\manifest.json`） | 81 页扫描混合 | extract 页标记 81 [实证: 2026-09-03]；第 10 页 OCR 检查点见 `tests\ab\expectations\anniu-p10.json` [实证: S008] |
| `tests\ab\assets\scan-cjk.pdf`（入仓合成） | 单页无文本层 | extract 报 `[needs_ocr: scanned]` [实证: 2026-09-03 本机]；OCR 检查点见 expectations（渲染源文本） |

- **什么叫过**：`cargo test --test regress` 全绿；基线差异必须能回指某次有意变更（P 编号）。
- **何时跑**：动提取、搜索、OCR、输出契约的代码后必跑真样本回归。

### 5. 验收测试

- **测什么**：对照需求口径验收：PRD 条目的达成标准、用户给定的可观察判据（如「5 至 10 秒一页」「掉字点全修」）。
- **落点**：cucumber BDD（D33）：业务语言场景在 `tests\features\accept.feature`，步骤绑定在 `tests\accept.rs`（harness = false 自管输出）；`R004` / `R005` 实机验收清单（门禁、真样本、交叉预建）；发版验收（资产 sha256 官方校验、解包冒烟、self update 路径）。
- **边界**：验收场景只测外部可识别行为，不测内部模块细节；testcontainers-rs 裁定不适用（纯 CLI 无可容器化依赖）。[经验: cucumber 官方定位；2026-09-03 用户供稿]
- **什么叫过**：`cargo test --test accept` 全绿且实机清单判据逐条实测满足并记录证据（机器、日期、数字）；oracle 独立于实现。
- **何时跑**：里程碑、发版前、平台接管时。

### 6. A/B 测试

- **测什么**：同一批对象资源上两个变体的**质量**（检查点命中、行召回、判别点）与**性能**（wall、秒/页）对比，支撑选型裁决。
- **落点**：`tests\ab\`（manifest 对象资源登记、expectations 检查点、reports 报告存档）；跑批器 `.tools\ab_run.py`；协议见 `tests\ab\README.md`。
- **什么叫过**：A/B 是对比不是门禁，跑批器退出码只表跑批成败；差异由人裁决，结论回填 S 文档（六态）。
- **规则**：检查点必须有独立来源（合成样本用渲染源文本，真样本用研究实证清单），禁止从被测输出反抄期望（G005 重言式禁令适用）；报告带日期与机器信息，不覆盖旧报告。
- **定位边界**：本仓 A/B 是**离线筛选门**（同资源双变体对比，淘汰明显劣化候选、支撑选型裁决），不是在线实验；随机分桶、灰度放量那套在线实验方法不适用于本 CLI 单二进制形态。[经验: 2026-09-03 用户供稿：离线评估是筛选门，在线实验是部署决策]

> 生态工具按需引入，不预先装（G005 懒人阶梯与依赖白名单适用）。

| 方向 | 生态件 | 触发条件 |

## 六、验收自查

加测试或建测试面时自查：

1. 落点对层：单元在 cfg(test)、集成在 tests\、A/B 在 tests\ab\
2. 每层「什么叫过」能说清；质量判断没塞进冒烟
3. 期望值与检查点有独立来源
4. 真样本基线变化能回指有意变更
5. A/B 报告落 reports\ 且裁决回填 S 文档
