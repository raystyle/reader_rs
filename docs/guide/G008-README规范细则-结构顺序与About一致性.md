# G008-README规范细则-结构顺序与About一致性

> 角色：**规范**：README 的结构顺序、About 一致性、写作增量与反模式禁令在本仓的逐项裁定。来源：2026-09-03 用户供稿《README 文档规范》（内容对照 GitHub Docs、standard-readme 与社区实践整理）。字符与命名基线继承 G001 / G004，冲突处以本文件为准；裁定四态沿用 G007：**已符合**（现状即如此）、**已落地**（本细则登记时落地）、**候选**（触发条件再动）、**不适用**（记原因防复问）。

## 一、定位与文件分工

README 是访客看到的第一份材料，回答四问：做什么、怎么装怎么用、谁维护怎么参与、什么许可。与仓内其它入口文件分工：

| 文件 | 受众 | 职责 |
| --- | --- | --- |
| `README.md` | 人（访客与用户） | 项目入口：价值说明、安装、快速开始、命令参考、贡献、许可 |
| `SKILL.md` | 编码 agent | 命令面与输出契约（`reader skill` 生成，逐字节守卫） |
| `AGENTS.md` | 协作者 | 协作规则最高约束 |
| About 与 Topics | 搜索与列表页 | 一句话定位与检索关键词，About 须与 README 首句逐字一致 |
| `CHANGELOG.md` 与 `docs\` | 用户与协作者 | 版本成果与深文档；README 只留链接不搬运 |

## 三、About 与 Topics

- 可以：About 与 README 首句逐字一致；长度以 120 字符为佳、250 为上限；本仓 About 维持纯中文（2026-09-03 用户裁定 [实证: PRD D40]），英文检索由 Topics 与正文关键词承担。
- 禁止：About 空置、口号化、只列技术名词、与 README 首句互相矛盾；Topics 堆砌空泛词或超过 20 个。
- 参考：Topics 现状 10 个英文词，覆盖领域、技术、用途 [实证: GitHub]；Website 与 License 等配套字段与 README 一致；改动 About 须同步 README 首句（义务见六节）。

## 四、写作与排版

> 基线继承 G001（树形、标题干净）与 G004（禁用字符、空格混排），此处只列 README 特有增量。

1. 先结论后细节：让读者 10 秒内判断值不值得用，再给安装命令。
2. 安装命令须在干净环境可复制执行：写明前置（工具链版本、平台）；每个代码块前用一句话说明命令做什么。
3. 仓内文件一律相对路径单行链接（如 `[LICENSE](LICENSE)`）；绝对 URL 只用于仓外目标（clone 地址、Releases、Issues、徽章服务）。
4. 代码块必标语言；命令示例标 `bash`（bash 与 pwsh 同形时注明），输出样例标 `text`。
5. README 只放「开始使用与贡献」所需信息；教程、深解、选型依据进 `docs\`，README 留一句链接。
6. 中文为主的 README 中命令、参数、格式名保留原文；标题不用空标题（如单写「示例」）。

## 五、反模式禁令

- 开头超长目录或徽章墙，读者仍不知项目是什么
- 安装命令在干净机器上失败（缺系统依赖、缺版本号）
- 功能列表替代可运行示例
- About 空白或与 README 首句不一致
- 用绝对 GitHub URL 链仓内文件（clone 后失效）
- README 与当前版本脱节（命令面变化不同步）
- 完整 API 与设计文档塞进 README（超 500 KiB 或不可扫读）

## 六、同步义务与门禁

- 命令面变化：README 与 SKILL 同步重生成（AGENTS 文档义务表「写改源码与配置」行）。
- About 变化：与 README 首句双向同步；发布时人工核对一次（含 Website、License 配套字段）。
- 门禁：文档四件（rumdl、md-heading-scan、md-ref-scan、md-char-scan，见 AGENTS 操作规则）；相对链接断链由 md-ref-scan 覆盖；渲染上限与 About 一致性为发布时人工核对项。
