# G005-测试标准细则-分层断言与门禁流程

> 角色：**本仓测试规则**。AGENTS 工作规则编码类「写测试时」的细则，三层展开：**分层与目录**、**断言与命名**、**门禁与演进**。
> 依据：2026-08-31 自 ohmyagents `R004-测试标准细则-分层断言与门禁流程.md` 引入并裁剪；其上游为三源对照研究（《Command-Line Rust》2022 地基、2026 社区综述、microsoft/rust-guidelines `c1d2efc`）。本文事实性断言标六态溯源，标准见 `docs\guide\G002-研究标准细则-结构与六态标记.md`。

## 一、分层与目录

> 分层按官方三层。

| 层 | 落点 | 测什么 | 约定 |
| --- | --- | --- | --- |
| 单元 | 源码同文件 `#[cfg(test)] mod tests`，`use super::*` | 私有 API、单函数边界、错误路径、不变量 | 正式构建不含测试代码 |
| 集成 | `tests\*.rs`，每文件独立 crate | 仅公开 API、模块协作、对外契约 | 不写 `#[cfg(test)]`；共享夹具放 `tests\common\mod.rs` 用 `mod common;` 引入 |
| 文档测试 | `///` 内 ```` ```rust ```` 代码块 | 公开 API 示例可编译可运行 | `cargo test --doc` 单独跑；lib 公开面少则暂不写 |

- 能用集成覆盖就不用单元：集成不依赖内部结构，重构时更稳。[实证: rust-guidelines M-INTEGRATION-TESTS；书第 3 章同向]
- `tests\` 每个顶层 `.rs` 是独立 crate；`tests\common\mod.rs` 不会被当成独立测试目标。[经验: 官方 cargo 约定]
- 本仓集成测试的 PDF 输入由 lopdf 现造（`tests\cli.rs` helper），期望值来自写入的已知文本，不依赖外部样本文件。[实证: 2026-08-31 tests\cli.rs]

## 二、断言与命名

> 意图对应方法；期望值必须有独立来源。

### 1. 意图到方法

| 意图 | 方法 | 本仓对应 |
| --- | --- | --- |
| 冒烟（活着即可） | 断退出码 0 | `reader --help`、`reader --version` |
| 集成（用户方式整跑） | assert_cmd 跑二进制，断 stdout/stderr/退出码 | `tests\cli.rs` 全部用例 |
| 回归（改动不破旧） | 黄金文件全量重跑 | 输出格式复杂后再上，现阶段断标记行 |
| 验收（对照外部标准） | oracle 生成期望 | 测试 PDF 内嵌已知文本即独立期望 |
| 不变量（任意输入成立） | 属性测试 | 页范围解析是候选；后置 |
| 性能 | 基准工具，不进断言 | 目标外 |

### 2. 断言规则

1. **期望值来自独立来源**：规范、黄金文件、属性约束。不得用被测同款逻辑复述期望值，不得镜像实现分支：重言式测试按构造通过，纯噪声，AI 生成测试高发。[实证: rust-guidelines M-TAUTOLOGICAL-TESTS]
2. **只断稳定字段**：标记行、退出码、stderr 关键词；放过 pid、时间戳、机器差异。[实证: 书第 14 章 Testing Underground]
3. **一个测试一件事**；失败信息能定位（panic 消息带原因与实际值）。[实证: rust-guidelines M-PANIC-MESSAGE]
4. **正例负例成对**：`success()` 与 `failure()` 对应写；无参数应失败并打用法是标准负例。[实证: 书第 1-2 章]
5. **错误路径必须覆盖**：空输入、缺文件、坏页范围、非 PDF 输入，不只测 happy path。[经验: 三源共同原则]
6. **测试体错误传播**：`type TestResult = Result<(), Box<dyn std::error::Error>>`，用 `?` 代替 `unwrap`。[实证: 书第 2 章]

### 3. 命名

- 测试名写成可读规格：动词加条件加预期（如 `search_finds_keyword_with_page`）。[经验: 社区惯例]
- 期望失败的负例名带 `dies_` 前缀，`cargo test dies` 可过滤。[实证: 书第 2 章]
- 常量收敛：测试文件顶部 `const PRG` / 路径常量用全大写。[实证: 书第 3 章]
- 重复模式收进 helper（如 `make_test_pdf` / `run(args)` 形态）。[实证: 书第 3、14 章]

## 三、依赖与闸门

1. **测试依赖白名单**：`[dev-dependencies]` 只进 assert_cmd、predicates、lopdf（造测试 PDF）；rstest、insta、proptest 等各设触发条件，不预先引入。[推断: AGENTS 写 Rust 规则的最少依赖原则对测试的适用]
2. **mock 策略**：本仓无外部服务依赖，真文件真解析，不默认 mock。[推断: 对照 M-MOCKABLE-SYSCALLS，本仓无网络/时钟/熵源边界]
3. **测试设施 feature gate**：若将来引入桩或假数据，收进单一 `test-util` feature。[实证: rust-guidelines M-TEST-UTIL]
4. **环境夹具**：测试 PDF 落系统临时目录，文件名带 pid 防冲突，用完即删。[实证: 2026-08-31 tests\cli.rs]

## 四、门禁

> 最小集本地化；CI 化后按第五节扩展。

1. **本地门禁三件**：`cargo fmt --all -- --check`、`cargo clippy --all-targets -- -D warnings`、`cargo test --locked`。
2. **锁文件**：Cargo.lock 入仓，测试跑 `--locked` 防依赖漂移。[经验: 社区门禁惯例]
3. **慢测**：大文件压测不进默认路径；默认反馈保持秒级。[实证: 书 biggie 分离原则]

## 五、演进路线

> 三段式，每段绿了再进下一段。

| 段 | 时机 | 内容 |
| --- | --- | --- |
| 第一段 | 本目标内 | `tests\cli.rs` 建档；search/extract 冒烟与正负例；本地门禁三件；AI 自检规则生效 |
| 第二段 | 输出复杂化后 | insta 快照管理期望（CI 禁静默改快照）；测试上量后引 cargo-nextest |
| 第三段 | 按需 | GitHub Actions 门禁；proptest（页范围解析）；多 OS 矩阵 |

## 六、AI 协作自检

> 本仓为 AI 协作仓，写测试前过一遍。

1. 期望值是否来自独立来源？若来自「我刚写的实现」，停，换规范或黄金文件。[实证: M-TAUTOLOGICAL-TESTS 点名 Agent 高发]
2. 是否先复现再固化？bug 修复先写失败测试再改代码。[经验: TDD 红绿循环，书第 3 章]
3. 断言的是行为（公开输出）还是实现（内部结构）？内部重构不应炸测试。
4. 快照与黄金文件不自动接受；变更必须可审。[经验: 社区快照纪律]

## 七、验收自查

写完测试自查：

1. 分层落点正确（单元在 `#[cfg(test)]`、集成在 `tests\`、公开 API 不塞 `mod tests{}`）
2. 期望值有独立来源；无重言式断言
3. 断言只含稳定字段；正负例成对；错误路径有覆盖
4. 命名可读；负例带 `dies_`；重复收 helper
5. 测试自清理；临时物不残留
6. 本地门禁三件通过
