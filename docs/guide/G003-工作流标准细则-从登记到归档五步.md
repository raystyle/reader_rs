# G003-工作流标准细则-从登记到归档五步

> 角色：**元规范**——一个想法从登记到归档怎么走。原 `PLAN.md` 的通用方法论节（五步、拆步骤标准、优先级取舍、经验指南）归类至此；PLAN 只留当前目标的计划。

## 一、从待办到完成的五步

1. **登记**：新想法进 `TODO.md`（优先级 + 一句话 + 登记日）
2. **立项**：开工前先在 `docs\proven\PNNNN-短名.md` 写方案（模板 `docs\guide\template.md`）
3. **执行**：按方案实施步骤推进
4. **验收**：按方案验收标准核对；POC 看退出码；文档看清单与断链
5. **归档**：完成后在 `docs\diary\YYYY-MM-DD-*.md` 记当天总结；方案回填「实施过程与经验」；版本/定位级成果另记 CHANGELOG

## 二、拆步骤的标准

- **一步一件事**：每个 example / 测试只证明一个部件
- **先方案后代码**：部件边界以方案为准；API 细节以对应研究与开发参考为准
- **每步带验收**：`cargo run --example` 退出码；会话结束后 `list-sessions` 无 POC 名
- **依赖明确**：闸门不满足不开下一步（如无 rmux 不开 pane POC）

## 三、优先级与取舍

| 优先级 | 含义 | 处理 |
| --- | --- | --- |
| 高 | 用户点名 / 阻塞其它项 | 先做 |
| 中 | 高项绿了再做 | 排队 |
| 低 | 收尾件 / 明确延后 | 目标末尾或下目标 |

原则：**一次只推进一个任务目标**（见 `GOAL.md` 锚点）。

## 四、验收的通用口径

- 待办全部已完成或明确跳过（跳过须写 `docs\mistakes\`（接编 MNNN）原因）
- 交付物不触碰红线（如 POC 不调 `kill-server`）
- `rumdl check .` 尽量零告警；新文档已登记 INDEX
- 研究与测试文档的关键结论标六态（AGENTS 写研究与测试文档规则）

## 五、过程内自修正循环

> 对应 AGENTS 操作规则「发现问题时」。

五步主流程执行中发现任何问题（文档错、规则缺、知识盲、行为坑），不停主线另起炉灶，就地走闭环：

1. **定位**：搜 `INDEX.md` 与相关文档，确认是否已有规则、研究、参考覆盖——有则按既有口径办，没有才新增。
2. **归类**：文档错修文档；规则缺补规则（AGENTS 或对应细则）；知识缺落研究（六态）；出错模式记 mistakes（接编 MNNN）；验证过的做法沉淀 references。
3. **修正**：改在源头；下游引用、索引、三原语同步。
4. **验证**：`rumdl check .` 加 `uv run --script .tools\md-ref-scan.py`；涉及结构再对账 INDEX 与磁盘。
5. **提交**：一事一提交；diary 记钩子；主线继续。

原则：问题不留在对话或记忆里；不重复造已有规则；临时补丁要么归档成正式资产、要么删掉。
